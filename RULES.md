# Rules

## Rule 1 — no personal names, no quoted conversations, no tool references

Rule is: nothing in this repository — code comments, notes, commit messages, file or folder names —
names a person, quotes a conversation, or refers to the tools used to write it. State the rule or the
reason instead, in this shape: "Rule is: [what must happen, what must not, and why]". A quoted remark
loses the situation that made it make sense; the next reader needs the intent. Project notes are
exactly four files: README.md (what this is, how to run it), RULES.md (this file), TODO.md (open
work), LOG.md (history). Nothing else is added.

## Rule 2 — one copy of the app, always the newest

Rule is: when this project is built, updated or installed, the new version replaces the old one in the
same place. Once the new version opens and works, every older copy is deleted in the same session:
dated or numbered app copies, backup copies, old release downloads and test builds. Build and install
steps overwrite the previous build and never save a new copy each time. Why: repeated builds left full
copies behind and filled the computer with over 100 GB of old versions.

## Public edition

Rule is: all general companion features belong in the Windows edition, including
the native price overlay. Private account records, pet identities, page designs,
backup destinations and previous repository history never ship in source or builds.
Rule is: reuse the existing feature modules and validated store; platform actions
pass through one narrow desktop adapter. Account identity is configured explicitly
and is checked at receipt, album, training, import and persistence boundaries.
Rule is: a star adds or removes a daily from My dailies. More dailies retains every
unstarred entry. Save errors preserve prior state and the interface reports them.
Rule is: the app opens ordinary game links only after a deliberate click. It never
buys, submits game forms or publishes page HTML. The optional local browser bridge
requires a pairing key, validates observations and listens on loopback only.
Rule is: the Windows overlay reads accessible visible browser content and draws its
own window. It never injects page code or performs a purchase. Stop is always available.
Rule is: every save validates and atomically replaces the state while retaining the
previous good save. Backups go only to a destination chosen by the current user.
Rule is: required third-party notices ship with every package. Only README.md,
RULES.md, TODO.md and LOG.md contain project notes.
Rule is: tests, simulated browser fixtures, installed Windows checks and real-account
checks are recorded separately. An unverified feature is never reported as verified.
Rule is: each new player controls their own lists and collection progress. Avatar
page-source imports are reviewed before saving, preserve existing progress, and
remain editable through the same manual checklist after import.
